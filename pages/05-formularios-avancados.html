Módulo 05 · Coleta de dados

Formulários avançados

Formulários conectam pessoas e sistemas. Um campo bem construído tem rótulo, nome, tipo adequado e validação previsível. Neste módulo, você combina acessibilidade, restrições nativas e agrupamentos complexos.

  • Nível intermediário
  • 5 tópicos práticos
  • Leitura estimada: 45 min
01

Rótulos e identidade

form, action, label for e name

O elemento <form> agrupa controles e define para onde os dados serão enviados (action) e como (method). Cada campo precisa de um name, que é a chave enviada ao servidor, e de um id para ser associado ao <label for="...">. O rótulo visível não substitui o name; eles cumprem papéis diferentes.

autocomplete ajuda o navegador a preencher dados conhecidos. O botão deve ter type explícito: submit envia, reset limpa e button não tem comportamento padrão. Um placeholder é apenas uma dica e não deve ser a única identificação do campo.

Resultado renderizado ao vivo

O tipo email ativa a validação nativa do navegador.

Acessibilidade: clicar no texto do <label> coloca o foco no campo. Isso beneficia todas as pessoas e é essencial para quem usa leitores de tela ou tem dificuldade motora.

02

O teclado certo para cada dado

text, password, email, tel, number, date, color, range e file

O type informa o tipo de dado e ativa teclados, controles e validações adequadas. email valida o formato básico; tel abre teclado numérico em celulares; number aceita passos e limites; date exibe um seletor de data; color abre uma paleta; range cria um controle deslizante; file permite anexar arquivos.

Resultado renderizado ao vivo

Aceita PDF, DOC e DOCX. O envio real depende do servidor.

Validação nativa não basta: o navegador pode ser contornado. Valide sempre no servidor e trate os dados com segurança. A validação no cliente melhora a experiência, mas não substitui a do servidor.

03

Regras declarativas

required, min, max, step, placeholder, autocomplete e pattern

Atributos de restrição descrevem o que é aceitável antes de qualquer JavaScript. required torna o campo obrigatório; minlength e maxlength limitam caracteres; min, max e step controlam intervalos numéricos e datas; pattern aplica uma expressão regular. O atributo title pode explicar o formato esperado e aparece na mensagem de erro.

Em pattern, a correspondência é feita com o valor inteiro, como se houvesse âncoras ^ e $. No exemplo, [0-9]{2} exige dois dígitos, [0-9]{4,5} aceita quatro ou cinco, e o hífen é literal.

Resultado renderizado teste o envio

Pattern: [0-9]{2} [0-9]{4,5}-[0-9]{4}

Pattern: [0-9]{5}-[0-9]{3}

Aceita de 1 a 50 pessoas, em passos de 1.

Dica: use inputmode para sugerir o teclado adequado sem mudar o tipo do campo. Exemplo: inputmode="numeric" em CEPs.

04

Muitas opções, uma boa organização

fieldset, radio, checkbox, select, optgroup, datalist e textarea

<fieldset> e <legend> agrupam controles relacionados. Botões radio com o mesmo name formam uma escolha única; checkbox permite várias seleções. <select> com <optgroup> organiza opções em grupos; <datalist> oferece sugestões sem restringir o valor; <textarea> permite texto multilinha.

Resultado renderizado ao vivo
Plano de estudo
Interesses

O datalist sugere valores, mas não bloqueia a digitação.

Máximo de 240 caracteres. O contador dinâmico é feito com JavaScript.

Radio x checkbox: use radio quando apenas uma opção pode ser escolhida e checkbox quando várias podem ser marcadas. O name comum é o que agrupa os radios.

05

Feedback imediato

O elemento output e uma pitada de JavaScript

<output> representa o resultado de um cálculo ou de uma ação do usuário. Ele é associado aos controles com o atributo for, que recebe os IDs dos campos de origem. Como HTML e CSS não recalculam valores, usamos uma pequena camada de JavaScript para atualizar a saída em tempo real.

Resultado renderizado interativo
50

Arraste o controle e veja o valor mudar no output.

Boas práticas: mantenha o output próximo do controle que o origina e forneça feedback textual claro. Não dependa apenas de cor ou de posição.

✓

Fechamento

Formulários claros e confiáveis

Você estruturou formulários acessíveis, escolheu tipos de entrada adequados, aplicou restrições nativas, organizou opções complexas e conectou um output a um controle. No próximo módulo, o foco é adaptar toda a interface a diferentes telas.

Exercício: crie um formulário de inscrição com nome, e-mail, telefone validado por pattern, seleção de trilha, interesses em checkbox, mensagem em textarea e um output que mostre a quantidade de caracteres digitados.
